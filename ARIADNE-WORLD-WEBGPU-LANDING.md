# Ariadne World/WebGPU clean landing

## Result

The audiovisual path now has one physical architecture and one observer
architecture:

```text
one multi-body Ariadne World
one material clock
one global ledger
       |
       +-- non-loading StereoListener
       +-- non-loading typed ObservationProgram
                         |
                         v
              content-addressed optical constitution
                         |
                         v
              persistent Rust/WASM WebGPU observer
```

There is no compatibility Terminal, fixed Terminal trace, JavaScript physics
kernel, audio-analysis fallback, page-specific channel index table, or alternate
one-body renderer in this path.

## Completed boundaries

- `WorldPlan` contains physical bodies, shared fields, and couplings only.
- Listener, observation schema, optical constitution, and presentation have
  separate digests.
- `mus-observation` carries typed F32/F64/U64 channels at absolute material
  ticks and a typed content-addressed `RunIdentity`.
- `BoundObservationProgram` resolves IDs and projections before runtime and
  accumulates without allocation.
- `mus-ariadne-webgpu-bridge` converts typed observations into fixed packet
  slots with no runtime name lookup.
- `OpticalClock` schedules transactionally and replays seeks in bounded fixed
  steps.
- Observer reset and constitutive update are separate passes.
- `WorldPresenter` binds persistent field views once.
- `ariadne-world-export` emits a complete content-addressed run bundle.
- `web/ariadne-world` verifies the bundle and runs the same Rust/WGPU graph in
  the browser.

## Claim boundary

The WebGPU field is a non-loading optical constitution. It does not contribute
to physical energy, game authority, sound, or future World state. A future
physical surface field or floating-body sector must be implemented in the
canonical World law vocabulary first; WebGPU may observe it immediately and may
be promoted to authoritative execution only through the separate physical
promotion gates.

## Required validation

Before merge or product promotion:

```text
cargo fmt --all -- --check
cargo test --release -p mus-observation
cargo test --release -p mus-ariadne
cargo test --release -p mus-ariadne-webgpu
cargo test --release -p mus-ariadne-webgpu-bridge
cargo test --release -p mus-ariadne-webgpu-web
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo check -p mus-ariadne-webgpu-web --target wasm32-unknown-unknown
cargo check -p ariadne-world-export
node --check web/ariadne-world/main.js
```

The workspace lockfile must be regenerated by Cargo after adding the browser
crate. GPU execution still requires a browser/device test matrix; source-level
or CPU-reference success is not a measured GPU-performance claim.
